# 验证矩阵

[返回首页](../README.md) · [安全边界](security-model.md)

这里记录能够支持的结论。**构建成功、静态测试通过、某一台电脑能联网，都不能单独证明所有程序不会直连。** 测试结果必须对应具体版本、系统和配置。

## 当前证据

| 检查 | 状态 | 能说明什么 |
| --- | --- | --- |
| 原生 helper 构建 | 已在本地及 Windows CI 通过初版构建 | C++ 可编译；不是网络行为证明 |
| PowerShell 语法 | 初版测试通过 | 脚本可解析；不保证所有运行分支 |
| helper 非法参数拒绝 | 初版测试通过 | 部分非法输入在操作 WFP 前被拒绝 |
| profile 参数校验 | 初版测试通过 | 被覆盖的非法端口、IPv6 预期出口被拒绝 |
| 通用版实际 WFP 阻断 | 待记录可复现结果 | 不能沿用私人部署脚本的测试结论 |
| 代理停止、恢复及出口检查 | 待记录可复现结果 | 需要包含断线时新建连接尝试 |
| Windows 10/11 全面兼容性 | 未完成 | CI runner 不代表所有用户系统 |
| 第三方安全审计 | 未进行 | 不应宣传已获独立安全认证 |

最新 CI 状态可在 [GitHub Actions](https://github.com/KardeniaPoyu/claude-proxy-guard/actions) 查看。新增验证时，应更新这一页，注明测试命令和对应的证据，不能只把“待验证”改成“已通过”。

## 自己部署后的验收

在可恢复的测试机或 VM 上执行。不要限制你唯一的远程管理程序，也不要停止维持远程连接的代理。使用专门的测试 exe 和配置，不需要真实账号 token。

| 步骤 | 操作 | 期望结果 |
| --- | --- | --- |
| 1 | 在安装策略前关闭目标进程，再安装策略 | 成功安装且可以查询验证 |
| 2 | 启动指定代理，发起经此入口的 TCP 请求 | 请求可达，出口等于预期 IPv4 |
| 3 | 尝试连接其他 IPv4 地址 | 被阻断 |
| 4 | 尝试连接本机其他 TCP 端口 | 被阻断，即使另一个代理正在监听 |
| 5 | 尝试 UDP 与 IPv6 出站 | 被阻断 |
| 6 | 停止指定代理，重新发起请求 | 失败；不改用其他端口或直连 |
| 7 | 恢复同一代理，再发起请求 | 恢复连接，仍是预期出口 |
| 8 | 改变代理配置、二进制或预期出口 | 启动检查拒绝继续 |
| 9 | 移除策略，再进行原受阻测试 | 行为恢复到系统原有规则决定的状态 |

步骤 3–5 应测试新建连接，不能用缓存页面是否显示判断。步骤 9 需要确保测试清理完成，不留下影响日常使用的策略。

## DNS 与工具需要单独测试

受保护程序可能让 Windows DNS 服务代发查询。只检查 HTTPS 出口 IP，不能证明 DNS 没有从其他出口发送。DNS 验证需要配合受控域名、代理日志或抓包，并明确测试的是哪个进程和解析方式。

Git、Python、Node、MCP 必须逐个确认实际发起连接的 exe。不要把对 `claude.exe` 的成功测试外推到所有子进程。

## 提交测试报告

使用仓库的“兼容性 / 网络验证报告”模板，至少记录：

- 项目版本或 commit、Windows 构建号、PowerShell 版本。
- 测试 exe 和代理软件版本；私人路径可以替换为示例路径。
- 测试步骤、成功/失败结果、是否为新连接。
- 清理方式与是否确认策略移除。

不要提交 token、真实代理凭证、完整配置、未经脱敏的网络抓包或账号信息。
