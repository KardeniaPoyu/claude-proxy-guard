# 常见问题

[返回首页](../README.md)

### 它能降低 Claude 封号概率吗？

没有可验证的保证。项目处理的是本机代理配置和指定 exe 的连接限制，不判断平台风控，也不提供绕过平台规则的账号方案。

### 是 API 付费还是我的订阅？

启动器不提供上游、不收费，也不重新结算 token。它把你自己的授权交给官方 Claude Code；可用功能、计费和授权范围由该账号及 Anthropic 规则决定。不要因为使用了代理就推断计费方式。

### 还需要 TUN 吗？

这套入口本身依赖 HTTP 代理与 WFP，不依赖整机 TUN。若你同时开启 TUN，它可能影响代理进程的上游路径；应检查真实出口。不能简单把“开了 TUN”当成所有程序无直连的证据。

### 是否支持 SOCKS5？

当前启动器使用本机 HTTP 代理 URL。可以由你自己的代理程序提供 HTTP/mixed 入口，但不能把一个仅支持 SOCKS5 的端口直接填进去。

### 断网后是否自动换其他节点？

启动器没有节点切换逻辑，也不会主动启用直连。**代理程序自身是否回退由它的配置决定。** 出口只在启动时检查，不是持续监督。

### DNS、IPv6、WebRTC 都解决了吗？

指定 exe 的 IPv6 连接按规则阻断。Windows DNS 可能由系统服务代发，需要另外验证。WebRTC 是浏览器相关行为，普通浏览器不是本项目默认覆盖的对象。

### 为什么不能直接复制 `claude.exe` 到另一个地方继续用？

WFP 规则绑定 exe 路径，新路径不继承旧策略。应该重新配置并验证，而不是把复制后的程序当作仍受保护。

### 其他软件会受影响吗？

不会全局改动代理或 TUN，但同一个受限 exe 路径的所有调用都会受到 WFP 规则影响，包括从普通终端启动的调用。因此不建议限制日常共享的 Python、Node 或 Git 安装。

### 换项目文件夹要重新创建配置吗？

通常不用。改变工作目录或桌面快捷方式即可；网络策略与程序路径关联。工作目录不是文件访问边界。

### 能保护 VS Code 的 Claude 图形扩展吗？

文档提供的是 VS Code 集成终端中的 CLI 入口。图形扩展、编辑器进程和 Remote-SSH 远端进程需单独分析，不能套用本机 `claude.exe` 的结论。

### 能在云端 Linux 上使用吗？

当前依赖 Windows WFP 和 DPAPI，不提供 Linux 云端部署方案。远端 CC 需要在远端设置网络限制，本机规则不会自动延伸过去。

### 为什么每次启动有 UAC？

原生 helper 查询/管理策略需要相应权限。提权只应发生在 helper 上；Claude 应保持普通用户权限。不要为了少一次弹窗而以管理员身份运行整个开发环境。

### 删除仓库为什么没有恢复网络？

策略是持久的。请保留配置并运行 `Remove-Policies.ps1`，成功后再删除文件。不要重置整机防火墙作为常规卸载方式。
