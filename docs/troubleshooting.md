# 排错

[返回首页](../README.md) · [操作手册](usage.md)

先用诊断命令收集状态：

```powershell
.\scripts\Test-Guard.ps1
# 需要验证实际 WFP 策略时，会请求管理员批准：
.\scripts\Test-Guard.ps1 -VerifyPolicy
```

诊断不需要你提供 token 明文。对外分享结果前，仍需检查路径、IP 和其他个人信息。

## 启动检查失败

| 提示或现象 | 常见原因 | 处理 |
| --- | --- | --- |
| 找不到 helper | 尚未构建或仓库目录结构改变 | 在开发者 PowerShell 中运行 `Build.ps1` |
| 策略检查失败 | UAC 未批准、安装未完成、策略被移除或修改 | 保留配置，运行 `Install-Policies.ps1`，再检查 |
| 没有正确的 loopback 监听 | 代理未开、端口错误、监听了所有网卡或 IPv6 | 检查代理实际端口；只监听 `127.0.0.1` |
| 代理进程或配置不匹配 | 同端口被另一个进程占用，或配置路径不符合要求 | 检查监听进程的真实 exe 与命令行；不要只看 GUI 节点名 |
| 程序或配置哈希改变 | 软件更新、编辑配置或替换文件 | 审查来源；代理更新用 `Update-ProxyPin.ps1`，受保护程序同路径升级用 `Update-ExecutablePin.ps1`；更换路径才重建配置 |
| 出口 IPv4 不符 | 选错代理、节点出口变化、配置有回退 | 核实预期出口和实际路由，查明原因后再更新配置 |
| 出口查询超时 | 上游不通、出口查询服务不可达、代理 TLS/认证问题 | 检查代理健康和网络；不要关闭出口检查绕过 |
| 检测到授权或代理覆盖 | 当前终端环境或 Claude 设置已有冲突 | 查明变量用途，在专用启动环境移除冲突；不要修改其他应用的全局设置 |
| 管理员终端被拒绝 | 用提升权限的窗口启动了 Claude | 改用普通用户 PowerShell；策略 helper 单独提权 |

代理入口需要 HTTP 支持。SOCKS5 端口不能只改成 `http://` 就变成 HTTP 代理。

## 授权问题

### 提示没有 token 文件

确认 `Save-Token.ps1` 与启动器使用同一个 `-ProfileDirectory`，并且保存时没有错误。不需要把 token 发给维护者。

### DPAPI 无法解密

确认当前 Windows 用户与保存 token 的用户相同。不要将 DPAPI 文件当作跨用户、跨机器可移植的凭证备份。使用自己有效的 token 重新保存。

### Claude 提示未登录或授权失效

1. 确认实际从本项目的入口启动，而不是普通终端里的另一个 `claude`。
2. 确认 token 属于你正在使用的账号且仍有效。
3. 检查是否使用支持相关授权方式的官方 Claude Code 版本。
4. 提供版本、错误文本和启动步骤，隐藏 token、邮箱和账号 ID 后提交问题。

不要在未经检查的命令中输出整个环境变量集合，里面可能有凭证。

## 工具连不上网络

- 限制某个 exe 不会自动配置它使用 HTTP 代理。工具必须支持相应代理方式。
- Git HTTPS 和 SSH 可能使用不同 exe、不同代理设置。
- 不同 Python/Node 安装路径是不同策略对象。
- 同一路径绑定了多个不同端口的策略时，阻断规则可能叠加。

先确认实际发起连接的程序路径，再检查代理支持。不要为了让工具联网而全局关闭规则。

## 更新和卸载失败

保留原配置目录、策略 ID 以及可用的 helper。先关闭受限制进程，再运行：

```powershell
.\scripts\Remove-Policies.ps1
```

如果使用了自定义目录，传入对应的 `-ProfileDirectory`。不要删除所有 WFP 策略或重置整机防火墙；那会影响其他软件和系统安全配置。若仍失败，提交脱敏错误码和版本信息。

## 报告问题需要什么

- Windows 版本、PowerShell 版本、Claude Code 版本、项目提交或版本号。
- 执行了哪个脚本，以及不含秘密的参数结构。
- 预期行为、实际行为、最短复现步骤。
- 代理是何种入口和软件版本；不要上传完整配置或节点凭证。
- 若是网络测试，说明是新建连接还是已有连接、测试前是否关闭目标程序。
