# 架构与安全边界

[返回首页](../README.md) · [验证矩阵](verification.md)

这个项目解决一个有限的问题：**尽量避免指定的本机 Claude Code 程序因代理变量缺失或代理不可用，意外建立其他出站连接。** 它不对账号风险、平台政策、代理服务质量作判断。

## 连接路径

```text
桌面快捷方式 / VS Code 集成终端
                  |
             Start-Guard.ps1
                  |
    配置检查 → WFP 检查 → 代理身份/哈希 → 出口检查
                  |
         加载独立配置与 DPAPI token
                  |
             claude.exe
                  |
       WFP：只接受指定 loopback TCP 端口
                  |
       本机 HTTP 代理 → 自己配置的上游 → 服务
```

图中的顺序表达职责，不是对每一个实现细节或线程时序的保证。任何启动检查失败都应终止启动。网络限制由持久 WFP 规则承担，而不是通过不停检查进程是否存活来模拟。

## 三层职责

| 层 | 本项目做什么 | 需要另外保证什么 |
| --- | --- | --- |
| 启动器 | 检查配置、程序和代理，加载指定配置与授权 | 不运行不可信 hooks、插件、项目脚本 |
| Windows WFP | 按 exe 路径阻断不符合条件的出站连接 | 实际系统、其他 WFP 驱动和已有连接上的兼容性测试 |
| 本机代理 | 本项目只检查其身份、磁盘文件及启动时出口 | 远端 DNS、上游固定、禁用直连和备用节点、代理自身更新 |

## WFP 策略

每个列入配置的 exe 对应一组独立 ID 的持久策略：

| 条件 | 动作 |
| --- | --- |
| IPv4 目标地址不是 `127.0.0.1` | 阻断 |
| IPv4 目标端口不是指定代理端口 | 阻断 |
| IPv4 协议不是 TCP | 阻断 |
| IPv6 出站连接 | 阻断 |

这些是阻断规则，不是保证连通的允许规则：系统里的其他限制仍可能让代理连接失败。规则按程序路径匹配，不按父子进程关系扩散。

### 代理停止时

指定端口没有代理监听，正常代理连接应失败。规则仍然存在，目标程序尝试其他地址或端口时应被阻断。重启 Windows、退出启动器或删除快捷方式不会移除规则。

### 代理仍在但上游失效时

是否切到其他上游由代理配置决定。启动器不解析所有代理软件的路由语义，也不持续证明出口仍未变化。**必须在代理配置层取消直连和其他节点回退。**

## 授权与秘密

- token 通过隐藏输入收集，用 Windows 当前用户 DPAPI 加密保存。
- 启动时必须解密到内存，再交给 Claude 的环境变量；运行中的明文不能被宣称“不存在”。
- 同一 Windows 用户、管理员、调试器或恶意程序可能访问进程环境与内存。
- 子进程可能继承授权环境变量。不要把不可信命令和 MCP 服务视为凭证隔离区。
- 用户自己负责账号、订阅和 token 生命周期。本项目不决定计费方式。

## 不在保护范围内

| 项目 | 原因或建议 |
| --- | --- |
| 未列入配置的 exe | 新进程可能直接联网；显式限制或使用独立 VM |
| 被复制或改名后的程序 | 路径不再匹配原规则 |
| Windows DNS 服务代发请求 | 不能仅凭某个 exe 的限制证明全系统 DNS 防泄漏 |
| 代理自身的直连/备用上游 | 代理拥有自己的出站能力，需要单独审查 |
| 文件读取和项目内容上传 | 独立配置目录不是文件沙箱；需要操作系统级隔离 |
| 已建立的连接 | 安装前关闭程序，再用新连接测试 |
| 管理员、同用户恶意代码 | 可以修改配置、程序、凭证或系统网络策略 |
| 浏览器、VS Code 图形扩展、远端 CC | 不属于本启动器自动覆盖的进程 |
| 账号“存活率”或平台风控 | 没有可验证的因果保证，本项目不作承诺 |

## 配置和更新是信任操作

哈希能发现磁盘文件变化，不等于验证供应商可信。代理配置里的远端规则集、运行时 API 修改、其他包含文件也可能改变行为，而未改变主配置文件哈希。更新后应检查实际路由，而不只是重新接受新哈希。

用户级 Claude 设置、管理策略和自行运行的脚本也可能影响行为。涉及代理、授权或配置来源的覆盖会被启动器尽量拒绝，但这不是抵御恶意用户设置的完整沙箱。

## 诊断和后台会话

诊断工具只通过已校验的专用 HTTP 代理发送固定 HTTPS 探针，不携带 token、不跟随重定向、不改用系统代理或直连。报告的 IP 检测只代表所测目标的当次响应。IPv6 检测失败、DNS/WebRTC 未测试，都不能作为“不泄漏”的证据。完整范围见[诊断说明](diagnostics.md)。

当前启动器支持前台终端及 VS Code 集成终端。Claude 的共享后台 supervisor 不一定继承当前终端环境；启动器拒绝 `--bg` 以及开头的 `agents` / `daemon` 命令。交互 `/background`、其他入口和参数组合不构成完整阻断，本项目尚未验证后台会话，不能据此前台检查宣称其已隔离。不要把已有前台 WFP 检查等同于所有后台/子进程的运行证据。
